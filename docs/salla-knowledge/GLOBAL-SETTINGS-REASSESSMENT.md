## 2. التصحيحات الثلاثة

### 2.1 ❌ «`__root.tsx` لا يملك `theme` في سياق SSR» — **غير صحيح**

**ما قاله التقرير:** «`__root.tsx` لا يملك `theme` في سياق SSR (`getTwilightContext` لا يعرض `theme`)»
⇒ ولذلك أُجّلت خلفية المتجر.

**الحقيقة:** `getTwilightContext()` لا يعرض `theme` **كمفتاح مباشر**، لكنه يعرض `settings`
بنوع `StoreContext`، و`StoreContext` يحمل `theme?: Theme`:

```ts
// dist/twilight/context.d.ts
export interface TwilightContext { settings: StoreContext; … }

// dist/api/store.d.ts
export interface StoreContext { store?: Store; theme?: Theme; languages?: Language[]; … }
```

```ts
const theme = getTwilightContext().settings.theme;   // ✔ متاح على السيرفر
```

**الأثر:** «خلفية المتجر» ليست مستحيلة تقنيًا. يمكن كتابة لون/صورة الخلفية inline على `<body>`
داخل `__root.tsx` **أثناء SSR** بلا وميض. التأجيل يبقى **قرارًا** (body خارج `.app-inner`،
وتعارض الوضع الليلي، وكلفة إعادة التحقق) — لكن **ليس** لأن المحرك يمنع ذلك.

> ملاحظة: `ctx.settings` يرمي `SettingsError` إذا كان المتجر فارغًا؛ استخدم `hasTwilightSettings()`
> للفحص، أو `ctx.settings?.theme`.

### 2.2 ⚠️ `display_copyright` — **غير مؤكَّد**

ذُكر في التقرير (2.1) كقيمة متاحة من `store.settings`. **ليس في جدول الوثائق الرسمي**،
ولا يوجد له مستهلك في الثيم. قد يكون حقلًا غير مُنمَّط يرسله الـAPI فعلًا — لكن هذا **يحتاج تحققًا
من رد `store/settings` لمتجر حقيقي**، لا استنتاجًا.

### 2.3 ⚠️ «المحرك يتجاهل `theme.color.text`» — صحيح، لكن **موثَّق**

التقرير قدّمه كاكتشاف من الكود. الوثائق تقوله صراحةً:
*«`--color-text` is `#222222`, not `color.text`»*. النتيجة نفسها، لكن **درجة التأكيد** ترتفع:
هذا سلوك مقصود ومستقر، لا صدفة إصدار.

## 3. معلومات جديدة لم تكن في التقرير (وتغيّر القرار)

### 3.1 `features` **لا تُقرأ في وقت التشغيل**

`features` في `twilight.json` تُخبر اللوحة فقط. **ليست في كائن الثيم**، ولا في `TwilightContextValue`.
⇒ أي معمارية تقرأ `features` لتقرر سلوكًا بصريًا **ستفشل بصمت**.

### 3.2 المحرك يقرأ ستة إعدادات بنفسه

`footer_is_dark` · `footer_layout` · `topnav_is_dark` · `sticky_add_to_cart` ·
`slider_background_size` · `header_is_sticky`

هذه تعمل حتى لو لم يقرأها الثيم. وأي إعداد عام جديد **لا** يحصل على هذه المعاملة —
يجب أن يُستهلك صراحةً، وإلا فهو حقل ميت.

### 3.3 `header_is_sticky` يُقرأ `false` داخل معاينة محرر الثيم

مهما اختار التاجر. ⇒ أي اختبار لقطة (harness) يعتمد على هذا الإعداد داخل المحرر سيعطي نتيجة كاذبة.

### 3.4 شكل قيمة الـdropdown قد يكون `string` أو `[{value}]`

`product_card_img_ratio` مُنمَّط للنوعين. **هذا المشروع آمن**: `scalar()` → `pickerValue()`
و`PICKER_KEYS` تبدأ بـ`value` ⇒ تُعيد القيمة الصحيحة في الشكلين.
لكن **أي قارئ جديد** يكتب `String(raw)` سيُنتج `"[object Object]"` — تحذير لأي `global_*` من نوع `items`.

### 3.5 الوثائق تحدّد **ستة أنواع** فقط، والنشر يفشل على غيرها

`boolean`, `items`, `string`, `number`, `collection`, `static`.
`slider` ليست تنسيقًا رسميًا ⇒ التحويل السابق إلى `integer` كان **تصحيحًا**، ويُسجَّل كذلك.

### 3.6 `groups` مفتاح أعلى تقرأه اللوحة عند النشر

اللوحة تقرأ فقط: `settings`, `components`, `features`, `support_url`, **`groups`**.
مخطط `groups` غير موثَّق. التقرير اقترح تجميع الحقول بعناوين `static` — وهذا يعمل اليوم،
لكن `groups` قد تكون الآلية الرسمية. **لا تُستخدم قبل التحقق.**

### 3.7 كتابة الإعدادات عبر MCP خطرة بطبيعتها

`salla_themes action=settings_update` يستبدل **مصفوفة الإعدادات كاملة** في `twilight.json`.
الأداة تدمج وتحرس الحذف غير المُسمّى، لكن الوثائق تنصح صراحةً بالتعديل من البورتال.
⇒ أي «نظام إعدادات» يُدار آليًا يجب أن يمرّ بـgit + البورتال، لا بـMCP.

## 5. المعمارية المعدّلة

### 5.1 ما يبقى كما هو

- Resolver واحد في `ThemeLayout`، قراءة مرة واحدة.
- `--gs-*` inline على `.app-inner` (لا `:root`).
- «الفارغ = لا يُكتب» ⇒ السلسلة تسقط طبيعيًا.
- التبنّي قبل إضافة الحقول.
- `productCardSettings.ts` يبقى النموذج المرجعي.

### 5.2 التعديل الأول — طبقة «قيمة سلة» تصبح مقروءة فعليًا

```
1. تجاوز البلوك (قيمة غير فارغة)
2. إعداد الثيم العام (global_*)
3. قيمة سلة الرسمية  ← تُقرأ الآن من theme + store.settings (لا من متغيّرات CSS فقط)
4. التوكن الافتراضي
```

الفرق عن التقرير الأصلي: المستوى 3 كان يعتمد على `--color-primary`/`--font-main` فقط.
الآن يضيف `theme.color.*`, `theme.settings.*`, و`store.settings.product.fit_type`
كقيم **مقروءة في JS**، متاحة في SSR.

```ts
// app/lib/storeSettings.ts — إضافة، لا استبدال
export function officialImageFit(store, theme): 'cover' | 'contain' | undefined {
  return store?.settings?.product?.fit_type ?? undefined;   // null ⇒ undefined
}
```

### 5.3 التعديل الثاني — خلفية المتجر تخرج من «مستحيل» إلى «قرار»

في `__root.tsx` (SSR، قبل أي رسم):

```tsx
const theme = getTwilightContext().settings?.theme;
const bg = theme?.settings?.store_bg_color;      // إعداد ثيم جديد — يحتاج قرارًا
…
<body style={bg ? { background: bg } : undefined}>
```

يبقى محظورًا: كتابة الخلفية على `:root` أو داخل مكوّن.
ويبقى شرطًا: **قاعدة أولوية مكتوبة** بين `--bg-store` في SCSS و`html.dark` و`color-mode-dark`.

### 5.4 التعديل الثالث — الوضع الليلي: سلطة واحدة

الخيارات الثلاثة، بصراحة:

| الخيار | السلوك | التكلفة |
| --- | --- | --- |
| **أ. اتباع سلة** | احذف `html.dark`؛ اقرأ `color-mode-dark` فقط | يفقد التاجر زر الليل في الهيدر (ميزة قائمة) |
| **ب. الثيم فقط** | أبقِ `html.dark`؛ تجاهل `color-mode-*` | ما يحدث اليوم: اختيار التاجر في سلة لا أثر له |
| **ج. سلطة واحدة موحّدة (موصى به)** | `html.dark` هو المصدر الوحيد، لكن **قيمته الأولية** تُقرأ من `color-mode-dark`، وزر الهيدر يكتب تجاوزًا محفوظًا | يحتاج تمييز «لم يختر بعد» عن «اختار فاتحًا» |

الخيار (ج) يحترم التاجر بلا نظامين متوازيين، وهو الوحيد المتوافق مع `/guide/styling` **ومع** ميزة الزر.

### 5.5 التعديل الرابع — `global_*` تبقى 4 كحد أقصى

| الحقل | النوع/التنسيق | المستهلك المطلوب قبل الإضافة | القرار |
| --- | --- | --- | --- |
| `global_radius` | `items` / `dropdown-list` (`theme`,`none`,`sm`,`md`,`lg`,`xl`) | `--radius-card` + `--selia-radius` (21 موضعًا) | جاهز بعد التبنّي |
| `global_container` | `items` / `dropdown-list` | `--container-max` (0 مستهلك اليوم) | **بعد** التبنّي |
| `global_rhythm` | `items` / `dropdown-list` | `--section-gap` (0 مستهلك) | **بعد** التبنّي |
| `global_accent_mode` + `global_accent` | `items` + `string/color` | `--gs-accent` | قرار التاجر (لا افتراضي) |

**لا** `global_font` (ينافس إعداد سلة)، **لا** `global_dark` (البند 5.4 قرار لا إعداد)،
**لا** `global_shadow` أو `global_motion` (صفر مستهلك).

### 5.6 التعديل الخامس — تحذيران إلزاميان في التنفيذ

1. **لا تقرأ `features`** لتقرير سلوك.
2. **لا تكتب `twilight.json` عبر MCP**؛ git + البورتال فقط.

## 8. سطر واحد للمالك

التقرير السابق كان محقًّا في «الطبقة موجودة والمكونات لا تقرأها»، ومحقًّا في «لا تُضف حقولًا قبل التبنّي».
الخطأ الوحيد المؤثر: **ظنّ أن الثيم غير متاح على السيرفر**، فحُجبت خلفية المتجر بلا داعٍ.
والدرس الجديد: **سلة تنتهي عند لون وخط** — كل ما بعد ذلك قرار تصميم يملكه الثيم، ولا يجوز انتظاره من المنصة.
